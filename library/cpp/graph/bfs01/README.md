# 01-BFS

辺の重みが 0 か 1 だけのグラフで、始点からの最短距離を求める。距離 `0` の辺は、今見ている頂点と同じ距離なので先頭側へ戻し、距離 `1` の辺は末尾へ追加する。両端キューを使うと、距離の昇順で頂点を処理できる。

重みが 0 と 1 以外にもあるときは、この手続きでは正しくない。[ダイクストラ法](../dijkstra/README.md) を使う。

## include

```cpp
#include "library/cpp/graph/bfs01/bfs01.hpp"
```

`template.hpp` は、このヘッダが読み込む。

## API

```cpp
vi bfs01(const vc<vc<pi>> &g, int s);
```

- `g[v]` は頂点 `v` から出る辺。要素は `{行き先, 重み}`。重みは `0` か `1`。
- 頂点番号は `0` 以上 `g.size()` 未満。
- 返り値 `dist[v]` は始点 `s` から `v` への最短距離。届かなければ `INF`。
- 経路の親は返さない。距離だけが欲しいときに使う。

## 計算量と制約

頂点数 `n`、辺数 `m` として `O(n + m)`。各頂点は距離が短くなったときだけキューに入る。グリッドなら、マス数と「上下左右へ進む」辺の本数がこの `n` と `m` になる。

## 使用例

`0` から `1` へ重み `0`、`1` から `2` へ重み `1`。`0` から `2` への距離は `1`。

```cpp
#include "library/cpp/graph/bfs01/bfs01.hpp"

int main() {
  vc<vc<pi>> g(3);
  g[0].push_back({1, 0});
  g[1].push_back({2, 1});
  auto dist = bfs01(g, 0);
  print(dist[2]);
  return 0;
}
```

出力:

```text
1
```

## こういう問題なら使う

「道は無料、壁を壊すとコスト 1」「マスの移動は距離 0、特定のマスだけ距離 1」。コストが 0 と 1 の二種類だけであることを問題文で確認する。コストが 3 種類以上ならダイクストラ法にする。

確認できた例題:

- [ARC 005 C - 器物損壊！高橋君](https://atcoder.jp/contests/arc005/tasks/arc005_3)。道は通れて、上下左右に接する壁を合計 2 回まで壊せる。ページを取得し、壁を壊す回数の上限があるグリッドの到達問題であることを確認した。壊した回数を頂点に含めると、通常の BFS でも解ける。壊すをコスト 1、道をコスト 0 とみると 01-BFS になる。

## 注意点

- 重みが 2 以上の辺を渡すと、距離の小さい順に処理されず、最短路にならない。
- `INF` は `1 << 60`。届かない頂点を `0` と区別するときに、`dist[v] == INF` を見る。
- グリッドの外側へ進む辺は、自分で入れない。この関数は、渡されたグラフだけを見る。
- 問題のマスが 1 始まりでも、グラフの頂点番号は 0 始まりで作る。

## 関連

重みが 0 以上の一般の値なら [ダイクストラ法](../dijkstra/README.md)。全部の辺の重みが 1 なら、通常の幅優先探索でよい。AtCoder Library に 01-BFS はない。
